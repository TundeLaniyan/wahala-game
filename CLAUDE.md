# WAHALA! - project conventions for Claude Code

Browser-only, offline, single-player (1 human vs 1-3 bots) Nigerian-inspired Bomberman-style game. **Authoritative design: `docs/GAME_DESIGN_BIBLE.md`.** Architecture: `docs/ARCHITECTURE.md`. Status/backlog: `docs/IMPLEMENTATION_STATUS.md`. Tuning/rule decisions: `docs/DECISIONS.md`.

## Commands
`npm run dev` | `npm run check` (typecheck + lint + vitest + build) | `npm test` | `npm run test:e2e` (Playwright; set `WAHALA_CHROMIUM=/opt/pw-browsers/chromium` offline) | `npm run simulate -- --matches 200` (bot batches). Debug URL flags: `?debug` (window.__WAHALA__), `?fps`, `?q=low|medium|high`, `?seed=N`, `?nobots`.

## CI and releases (docs/CI.md)
- CI: plan + parallel fast checks (typecheck/lint, Vitest, one `vite build`) -> Playwright shards on separate runners (`--shard=i/N --fully-parallel`, 1 worker each, serving that build) -> merged report (`scripts/ci/report.ts` fails unless every listed test ran exactly once) -> `CI gate` -> deploy. Fix slow or hanging tests at the cause; do not raise the shard timeouts or reintroduce a single long E2E job.
- Only `.github/workflows/deploy.yml`, called by CI after the gate, publishes the Pages preview, and only from its `PUBLISH_BRANCH` with the tested `dist` artifact. Never add another publishing workflow, a manual deploy trigger or a rebuild in deploy. Old feature branches still carry publishing workflow copies: do not push to them (docs/CI.md, "Single publisher").
- Documentation-only commits (`docs/`, `reference/`, `README.md`, `CLAUDE.md`) skip the browser suite and the deploy (`scripts/ci/plan.ts`); do not push commits just to record that CI passed.

## Non-negotiable rules
- Stack: TypeScript strict, Vite, Three.js, React + Zustand (UI only), Vitest, Playwright. No backend, DB, auth or sockets.
- `src/sim` is pure and deterministic: no DOM, Three, React, `Math.random`, `Date.now`. Time = ticks (60/s). Randomness = seeded `rng.ts`. ESLint enforces this. `src/ai` may import only `src/sim`.
- No game rules in render/ui/audio/input. Rendering reads state and consumes `SimEvent`s.
- All balance numbers live in `src/sim/config.ts`. Characters/vehicles/pickups/arenas are data.
- Humans and bots send the same `Intent`. Bots only see `observe()` output, never hidden pickups or RNG.
- Game rules that are LOCKED in the Bible must not drift: generator is the primary weapon; Okada is a mount (one-hit shield) - it is also a public vehicle (voucher / VEHICLE GENERATOR carrier) only where an arena allows it, never a character's own; vehicles are public and never tied to a character (decision VG1, amended 2026-11-02); vehicle damage accumulates over separate blasts; Kill-Switched generators still explode from flame/vehicles; carry adds exactly +1s once; simultaneous final deaths = draw; no health bars.
- Never reformat `docs/` or `reference/` (Prettier ignores them).
- Any gameplay/tuning change: log why in `docs/DECISIONS.md`. Never claim a feature works without a passing test or a real browser check.

## Presentation assets (overhaul branch)
- 3D models are glTF files in `src/assets/models/` generated by deterministic Python in `tools/assets/` (numpy/scipy/Pillow only; see `docs/ASSET_PIPELINE.md`). Re-run the relevant `build_*.py` after changing a generator and commit the `.glb`. Never hand-edit `.glb`/`.jpg` outputs.
- All models load through `src/render/assets/library.ts`; each consumer has a procedural fallback (`characters.ts`, `vehicles.ts`, `generator.ts`, `props.ts`) so the game still runs if a file fails to load. Conventions (Y-up, front +Z, node/material names the game looks up) are in the asset pipeline doc.
- Camera: standard matches use the fixed whole-arena camera (`render/cameraModes.ts` mode `arena`); never make it follow a player or zoom. The follow camera is the `stadium` mode, used only by City Rumble (`cityRumble`, up to 32 competitors; `?cam=stadium` forces it for testing).
- Arenas: nine standard 15 x 11 arenas + City Rumble in `src/sim/arenas/`. Arena rules and balance are `ArenaDef.config` overrides (e.g. the Power Yard full-line blast) - never `if (arenaId === ...)` in rules code. Each arena's stage hazards (`stageHazards`, `floorTraps`) are always on: no menu switch (`MatchSettings.stageHazards` is for tutorials/tests only). Presentation per new arena: `src/render/arenas/<name>.ts` (look + set + floor), registered in `newArenas.ts`. Report: `docs/NINE_ARENAS_CITY_RUMBLE.md`.
- Characters: the 18-character roster (3 heroes, 7 bosses, 8 enemies) is generated by `tools/assets3/` (CC0 MakeHuman anatomy -> garments cut from the body -> the same 22-bone skeleton; `docs/CHARACTER_PRODUCTION_ROSTER.md`). Heroes are eager (`models/char_<id>.glb`); enemies and bosses are on-demand (`models/lazy/`, `AssetLibrary.ensure`), chosen by `enemyLooks.dedicatedModelOf` (variant or boss name); the previous kit look is the fallback and `?legacyEnemies` forces it. Never hand-edit the GLBs; re-run `python3 tools/assets3/roster.py <id>`.
- Look: gritty, adult Lagos street life, not a bright toy board. Every lit material gets the world-space weathering patch (`render/grit.ts`, class via `userData.grit` on an ancestor); per-arena light/fog/lamps in `render/arenaLook.ts`; each arena's surroundings are their own module in `render/arenas/` (bus terminal / market / construction site) and must keep everything off the board and low on the camera (south) side. Background people are real rigs via `render/life/StreetLife.ts`; atmosphere via `render/fx/Ambient.ts`. `scripts/quick-shot.mjs` (and its `INSPECT` close-ups) is the art-review tool: judge the rendered picture.
- Mandatory endgame floor traps (0:30 and 0:15 waves) are a rule, not an option: never add a setting that disables them (decisions G3-G5).
- Characters are skinned glTF + `AnimationMixer`; animation choice derives from sim state/events in `render/views/PlayerViews.ts` only. Do not put rules in animation code.
- Audio: every effect and ambience bed is synthesised at runtime (`src/audio/recipes`). The generated music, Kokoro TTS voices and generated Lagos ambience from `claude/wahala-lagos-audio` were **rejected by the founder and removed**; do not generate or reintroduce music, voices or ambience yourself (never call a TTS service). The founder's own approved **Gemini TTS voice clips** ship: masters in `tools/audio/voices/masters/`, added only with `tools/audio/voices/import_voices.py` (which writes `public/audio/voices/voices.json` + `recorded.json` + MP3s), never by hand; the rejected `conductor_cms_01` never ships. Voice triggers are the founder manifest's names, fired from `src/audio/pidginReactions.ts`. Music only through `public/audio/music/manifest.json`, other recordings through `public/audio/slots.json`; update `tests/audio/assets.test.ts` deliberately. Read `docs/AUDIO.md`. Never describe synthesised or TTS sound as authentic recordings. The founder-approved WAHALA! originals (the seven district songs, the *Lagos No Dey Sleep* menu / boss music and result stingers; approved 2026-11-25) ship through the same manifest and slots (decision AU4, `docs/AUDIO_RELEASE.md`): files and checksums are managed only by `npm run audio:release-build` / `audio:release-verify` (`tools/audio/release/`), never edited by hand; the Pixabay tracks stay as each arena's fallback; the originals ship on the founder's documented, risk-aware authorisation of 2026-11-25 (`public/audio/release-clearance.json` status `founder-authorised`: not a legal clearance, scoped to the digest of `SHA256SUMS`; no explicit prohibition was found in Google's terms, no grant or indemnity either; `docs/AUDIO_RIGHTS_ASSESSMENT.md`, decision AU5): the deploy workflow publishes them only with a complete `cleared` / `founder-authorised` record, never claim a licence or legal opinion that does not exist, and the Gemini conversation address is never committed (hash reference only). The song *Lagos No Dey Sleep* (SHA-256 `e4b6314d4c27cc2719e51f7cc9f97f4df03dec8920696e744211afc29be3bebc`), its stems and the district recordings are not committed. Any OTHER unapproved original-theme material (the generic rumble mix, logo sting, campaign cues, proposed arena mappings) stays an opt-in audition overlay only (`?audiodraft`, `src/audio/candidates.ts`, decisions AU1-AU3, `docs/AUDIO_INTEGRATION.md`, `docs/AUDIO_PRODUCTION.md`, `docs/AUDIO_DISTRICTS.md`) until the founder approves it.
- HUD: no crowd speech bubbles or other transient text over the board. Notices, stage alerts, the arena rule and the optional subtitles (setting, default off) live in the HUD rail beside the board (`ui/HudRail.tsx`, sized from `renderer.boardScreenCorners()`); `e2e/voices.spec.ts` checks nothing covers the bottom row.

## V2 gameplay (branch `claude/wahala-gameplay-rumble-v2`, docs/GAMEPLAY_V2.md, docs/V2_CONTRACTS.md)
- Exactly two action buttons on every device: A tap = generator (`Intent.place`), A hold = Remote Detonator (`Intent.detonate`, decisions OJ2-OJ3; under QUICK HANDS a held A lays a generator on every tile, `Intent.placeHeld`), B tap = one deterministic context special (`Intent.special`, `sim/systems/actions.ts`: adjacent attackable opponent -> melee, else VEHICLE GENERATOR, else GLOBAL KNOCKDOWN, else voucher -> one-press auto vehicle, else nothing), B hold also sets off the remote (`input/specialHold.ts`: one tap/hold mechanism for both buttons). Never add a third permanent button or move them.
- Kick / punch / disarm / pass are mutually exclusive contact abilities (`Player.contact`), triggered by walking into a generator (`sim/systems/contact.ts`). Carry is out of normal play (legacy code only).
- Wahala Crush is mandatory in every standard match (no Classic Timer choice). Eliminated Classic players are sideline spectators (`systems/spectators.ts`).
- City Rumble is the flagship: Survival / Deathmatch / Team rulesets in `sim/modes.ts` (one simulation); power comes from credited eliminations (`systems/attribution.ts`, `systems/rewards.ts`), crates drop nothing in Rumble. Five V2 stages + the original district (`RUMBLE_ARENA_IDS`), one signature track each.
- Seven bot levels (`Difficulty`, `ai/profiles.ts`), Rookie default; bots press the same one-press special as humans.
- Camera shake is bounded (`render/shake.ts`), off on touch and with reduced motion.

## Conventions
- Small modules, explicit interfaces, no god classes, no circular imports; prefer composition; inject dependencies only where it helps tests.
- Tests: scenario-style (`tests/helpers.ts` `sandbox()` etc.). Add a regression test with every bug fix.
- `base` is `/wahala-game/` for production builds (GitHub Pages). Use relative/Vite-resolved asset URLs only.
- Commit per milestone; update `docs/IMPLEMENTATION_STATUS.md`.

## Stitch menu (branch `claude/wahala-stitch-uiux-v1`, docs/STITCH_UI.md, decisions UI1-UI11)
- The main menu is a short flow with no numbered steps: Home (PLAY, STORY CAMPAIGN / CONTINUE STORY, LEARN TO PLAY, small Settings and Sound) -> Choose How to Play (`play`: Quick Match, Classic Blast, City Rumble, all visible; Quick Match starts a 1 human + 2 Rookie bot Classic match at once, `app/quickMatch.ts`) -> Match Setup (battle style, "Select Arena", opponents, rules, START MATCH) -> Fighter -> Ready/Review -> Start Match. Six-screen redesign: `docs/SIX_SCREEN_UI.md`, decisions SX1-SX10; `ui/menu/redesign.css` is loaded after `flow.css`. EXIT MATCH in the pause menu always asks "Leave this match?". Bot difficulty is one slider (`ui/menu/DifficultyControl.tsx`). Layouts: `ui/menu/flow.css` over `menu.css`. Navigation is the pure state machine `app/menu.ts` in `UiState.menu`; screens live in `src/ui/menu/` and edit the real `GameSettings` / `audioPrefs` only through `commands`. Never add a parallel setup state.
- Menu text about modes, arenas and fighters comes from the sim registries / config and `src/tutorial`; never show invented stats, ranks, locks, rewards or online features from the Stitch mockups.
- Menu art: `tools/ui/build_menu_art.py` builds `src/assets/ui/*.webp` from `tools/ui/masters/` (crops the mock HUD, removes brand marks); never hand-edit the outputs. Fonts are bundled (`@fontsource`), no CDN.
- Keyboard / gamepad menu input goes through `app/menuNav.ts` before the match; Esc in the pause menu's Settings closes Settings and keeps the match paused.
- Phones: every menu works in portrait and landscape, tap targets >= 44 px, safe areas; `e2e/menu.spec.ts` sweeps the sizes. `scripts/menu-shots.mjs` is the screenshot review tool for the menus.

## Graphics quality (branch `claude/uiux-adaptive-performance-v1`, docs/PERFORMANCE.md, decisions PF1-PF10)
- `GameSettings.quality` is `'auto'` (default) or a preset (Very Low ... High). The ladder is `src/render/quality.ts` (8 rungs, every budget non-decreasing); the device estimate, the controller and the learned rung are in `src/render/perf/`. Render-only: `src/sim`, `src/ai` and `src/input` must never see quality, and nothing in the quality system may change input timing, bomb timing, collisions, blasts or match rules.
- Add a new render budget as a field of `QualityProfile` with a value on every rung (the ladder test enforces the order), and make it LIVE (applied without a rebuild) unless it is decided at arena build; say which in the field's comment. A manual preset is never changed by Auto.
- Threshold changes go in `DEFAULT_ADAPTIVE` with a test in `tests/render/adaptive-quality.test.ts`; do not add ad-hoc FPS checks elsewhere.

## Lagos arenas (branch `claude/wahala-lagos-arenas-v1`, docs/OSHODI_METROPOLIS.md, decisions LA1-LA12)
- Source: the Canonical Lagos Map Build Bible v2; one arena at a time on the Ojuelegba pattern (graph -> sim data and tests -> real-object cover -> landmarks -> screenshots). Ojuelegba is the reference and stays unchanged. Names, signs and shops are fictional (no real brand or near-copy); no one-player bosses yet: only the reserved `ArenaDef.futureBoss` metadata, and never a real person's name, face, voice, clothing, biography or branding.
- Oshodi Transport Metropolis is the canonical `rumbleOshodi` (it replaced the old generic Oshodi Rush Hour, founder decision 2026-10-30; there is no second Oshodi Rumble stage). Railcars are the `train` sweep style on track lanes (`=` tiles): always warned >= 3.5 s, one step from a track-free tile, solid portal blocks at both ends, one lethal stage event at a time. The engine is single-level: "skywalk" / "grade-separated" routes are ground-level routes that share no tile with a road or track lane.
- Day and night share geometry: `ArenaArt.nightLook` is shown behind `?tod=night` (`render/timeOfDay.ts`). Cover maps are a letter per `#` (`oshodiMetroCoverMap.ts`) and must match the sim layout (tested); cover never spills over walkable floor.
- Audio for new arenas: synthesised cues only; no music, voice or recording is added without a founder assignment (default playlist until then; Oshodi keeps the founder's Oshodi track and voice zones).

## Kill streaks, combat and touch input (branch `claude/wahala-streaks-combat-input-v1`, docs/STREAKS_AND_COMBAT.md, decisions MI1-MI5, CB1-CB4, SK1-SK4, VG1-VG4, GK1)
- Fixed initial loadout, no selection menu yet: 3 credited kills QUICK HANDS (18 s, +5 generator charges, hold-A lays, presses never lost), 5 VEHICLE GENERATOR (any public vehicle carries a live generator: 3 s fuse from launch, thrown at about 2 s at a rival, owner never targeted nor caught), 7 GLOBAL KNOCKDOWN (visible objects from the building side flatten every rival for 2 s, non-lethal). `config.streaks`, `sim/systems/streaks.ts` / `vehicleGenerator.ts` / `knockdown.ts`. Earned once per threshold, consumed once, lost on death; kills, deaths and assists are never reduced. Assists pay no reward (future work).
- Close attacks are data in `config.skills.attacks` (startup, whiff / hit recovery, per-target lockout, displacement, daze): Punch (`push`) fast and light, Shove slow and positional, Daze Punch slow and heavy. Nothing roots the attacker; never make two attacks identical again (`tests/combat-attacks.test.ts` checks no attack dominates; `npm run combat-balance` measures them).
- Touch input (`input/moveGate.ts`, touch device at the full assist level ONLY): a press during a daze / slide / teleport arrival is kept (MI1), the newest direction cancels an owed diagonal step (MI2), a player standing in a blast footprint skips the settle and may step through it, never nearer the generator (MI4). Keyboard and gamepad streams are unchanged (`tests/mobile-input-reliability.test.ts` section 7). `?debug` / `?trace` record the touch -> gate -> sim trace (`input/trace.ts`).
- Vehicles: `Player.voucherKind` / `StreakRewards.vehicleGenerator` carry the drawn kind (`drawVehicle`, match RNG, `config.vehicles.allowed`); Rumble stages allow the Okada. Tutorials always use a Danfo.

## Classic raid AI and lighting (branch `claude/wahala-classic-ai-lighting-v1`, docs/CLASSIC_RAID_AI.md, docs/CLASSIC_LIGHTING.md, decisions RA1-RA7, NL1-NL15)
- Classic raids carry the campaign tactics layer WITHOUT its combat model (`raidTacticsFor`, `tacticsCombat(config)` is undefined with `classicRaid`): routes derived from the board (`sim/raid/routes.ts`), bounded pursuit, slower-than-player pace, perceived generators only (sight / short hearing / memory). Every other match type is byte-identical (`tests/raid-ai-isolation.test.ts`); keep it so.
- `enemySeesPerson` (`systems/sight.ts`) is the one person-sight rule; a light term may change only its range, never the line rule. `Player.facing` is the view / torch direction.
- Raid art is registered under the SIM arena id (`raidWarehouseDispatchDepot`, ...), tested on a real game of every raid; lit raids must stay at least as readable as Danfo Bus Park on the same preset (`tests/render/classic-readability.test.ts`).
- Night raids are data (`RaidDef.lighting`; only the Records Vault). Lit tiles are a pure sim rule (`sim/raid/light.ts`); the darkness is the grit patch's per-tile mask, never shadows or new dynamic lights. Quality never changes what is lit; danger lanes and warnings stay above the dark; no flashlight button (two buttons only). Detection (`systems/nightSight.ts`) applies to calm guards only, inside their own drawn torch cone with line of sight, with a reaction delay; `lighting.detection: false` turns it off.
- Release integration with the 18-character roster (decisions RI1-RI5, docs/RELEASE_INTEGRATION.md): a seat re-dressed mid-match must release its skeleton; down seats start hidden; the loading screen waits (bounded) for on-demand models. `?qaraid=<raidId>` is a TEMPORARY founder QA entry that never writes the save: remove it per docs/QA_ENTRY.md after the founder's phone tests.

## Mobile data and loading (branch `claude/wahala-mobile-optimization`, docs/MOBILE_PERFORMANCE.md)
- Hosting is GitHub Pages: `Cache-Control: max-age=600` on everything, gzip only (no Brotli), no custom headers. Do not rely on HTTP caching headers; the offline cache worker (`src/platform/sw/sw.template.js`, built into `dist/sw.js`) is what keeps hashed files for good. It is skipped under automation unless `?sw`; `?nosw` removes it.
- 3D models load on demand (`src/render/assets/modelNeeds.ts`). The boot loads only the hero cast; a start loads its arena's set (`GENERATED_ARENA_MODELS`, derived from a real recording by `scripts/perf/asset-access.mjs` + `gen-model-needs.mjs`); the Ready screen prefetches it; anything unknown (campaign, raids) loads everything. **Adding a model or an arena that uses a different model set means re-recording** (`docs/MOBILE_PERFORMANCE.md`, "Re-recording the model sets") and keeping `e2e/model-loading.spec.ts` green: no model the renderer asked for may be missing (`__WAHALA__.assetAccess().missed` is empty), and the scene must equal `?preloadall` (the old boot).
- Shipped `.glb` files go through `scripts/vite/optimizeModels.ts` (meshopt + textures shared by several models served once). The source files are never edited. The optimiser verifies its own output and keeps the original on any doubt; do not loosen `MAX_POSITION_ERROR` / `MAX_SKINNED_POSITION_ERROR` without a visual review. `WAHALA_NO_GLB_OPT=1` builds without it (A/B).
- Data Saver (`GameSettings.dataSaver`, Settings > Audio): network only. It plays `public/audio/music/lite/*.mp3` (96 kbps, `tools/audio/make_lite_music.sh`); graphics and battery stay the Graphics quality setting. New music needs its lite file (`tools/audio/lite_manifest.mjs`); `tests/audio/assets.test.ts` enforces it.
- Measure with `scripts/perf/*` (real-browser wire bytes, frame time, memory); software-rendered Chromium is not a phone, so say so whenever quoting its numbers.

## City Rumble online, integrated but NOT public (branch `claude/wahala-online-integration`, docs/ONLINE_INTEGRATION.md, docs/CITY_RUMBLE_ONLINE.md, decisions ON-integration)
- GitHub Pages stays the fully offline game. Online is compiled in ONLY by a build with `WAHALA_ONLINE_ENABLED=true` AND `WAHALA_ONLINE_URL=<endpoint>` (`npm run build:online`, template `ws://{host}:2567`; `{host}` = the page's own hostname), and shown ONLY with `?online` on top. No URL parameter can enable it in a public build; the endpoint never comes from the URL or from source defaults (no localhost / LAN / tunnel address in `src/`). A default build must contain no online code, no WebSocket and no such address: `npm run check:static`, `tests/online/public-bundle.test.ts`, `tests/online/import-guard.test.ts`, `e2e/online-public-offline.spec.ts` assert it. Do not weaken them.
- The ONLY edge from the main bundle into online code is a dynamic `import()` lexically guarded by `__WAHALA_SERVER_ONLINE__` (`src/online/rumbleEntry.ts`; the menu screen and the in-match overlay use the same guard). `src/net/**`, `src/app/rumbleOnline*.ts`, `src/ui/online/rumble/**`, `server/**` are online-zone code; `MatchController`, `session.ts`, sim, ai, input, render and campaign never import them (`src/app/remoteMatch.ts` is the types-only port).
- An online match is the offline presentation pipeline fed by a server replica: `MatchController.startRemote(driver)` (`app/remoteMatch.ts`). The local seat is `controller.localSeat` (never assume player 0 outside campaign code). The server is authoritative for everything; the client sends only `{s,m,h,b}`. Local walking prediction (`src/net/client/prediction/`, docs/ONLINE_PREDICTION.md) is presentation only: an in-place overlay of seven step fields that is reverted before every `replica.advance`; never let it feed scores, results, the hash or anything the server receives.
- Disconnects (server, configurable): grace (`RUMBLE_GRACE_SECONDS`), a bot plays the seat without pausing the match, the same fighter returns within `RUMBLE_RECONNECT_SECONDS`. A human's PERSONAL kills/deaths/assists count only human-controlled time; bot numbers are separate fields. Ranking / reward policy is OPEN (docs/CITY_RUMBLE_ONLINE.md section 8): do not invent it.
- Local development: `npm run dev:online` (server + Vite with the flags, LAN URL printed), `npm run test:online-e2e` (two real browsers against the real server; local only). `server/` is its own npm package. Do not deploy a server, buy hosting or create accounts without founder approval.
