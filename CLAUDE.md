# WAHALA! - project conventions for Claude Code

Browser-only, offline, single-player (1 human vs 1-3 bots) Nigerian-inspired Bomberman-style game. **Authoritative design: `docs/GAME_DESIGN_BIBLE.md`.** Architecture: `docs/ARCHITECTURE.md`. Status/backlog: `docs/IMPLEMENTATION_STATUS.md`. Tuning/rule decisions: `docs/DECISIONS.md`.

## Commands
`npm run dev` | `npm run check` (typecheck + lint + vitest + build) | `npm test` | `npm run test:e2e` (Playwright; set `WAHALA_CHROMIUM=/opt/pw-browsers/chromium` offline) | `npm run simulate -- --matches 200` (bot batches). Debug URL flags: `?debug` (window.__WAHALA__), `?fps`, `?q=low|medium|high`, `?seed=N`, `?nobots`.

## Non-negotiable rules
- Stack: TypeScript strict, Vite, Three.js, React + Zustand (UI only), Vitest, Playwright. No backend, DB, auth or sockets.
- `src/sim` is pure and deterministic: no DOM, Three, React, `Math.random`, `Date.now`. Time = ticks (60/s). Randomness = seeded `rng.ts`. ESLint enforces this. `src/ai` may import only `src/sim`.
- No game rules in render/ui/audio/input. Rendering reads state and consumes `SimEvent`s.
- All balance numbers live in `src/sim/config.ts`. Characters/vehicles/pickups/arenas are data.
- Humans and bots send the same `Intent`. Bots only see `observe()` output, never hidden pickups or RNG.
- Game rules that are LOCKED in the Bible must not drift: generator is the primary weapon; Okada is a mount (one-hit shield, never an attack vehicle); exactly three attack vehicles (Danfo, taxi, Keke) fixed per character; vehicle damage accumulates over separate blasts; Kill-Switched generators still explode from flame/vehicles; carry adds exactly +1s once; simultaneous final deaths = draw; no health bars.
- Never reformat `docs/` or `reference/` (Prettier ignores them).
- Any gameplay/tuning change: log why in `docs/DECISIONS.md`. Never claim a feature works without a passing test or a real browser check.

## Presentation assets (overhaul branch)
- 3D models are glTF files in `src/assets/models/` generated by deterministic Python in `tools/assets/` (numpy/scipy/Pillow only; see `docs/ASSET_PIPELINE.md`). Re-run the relevant `build_*.py` after changing a generator and commit the `.glb`. Never hand-edit `.glb`/`.jpg` outputs.
- All models load through `src/render/assets/library.ts`; each consumer has a procedural fallback (`characters.ts`, `vehicles.ts`, `generator.ts`, `props.ts`) so the game still runs if a file fails to load. Conventions (Y-up, front +Z, node/material names the game looks up) are in the asset pipeline doc.
- Camera: standard matches use the fixed whole-arena camera (`render/cameraModes.ts` mode `arena`); never make it follow a player or zoom. The follow camera is the `stadium` mode, reserved for the future 32-player stadium (`?cam=stadium` to test).
- Look: gritty, adult Lagos street life, not a bright toy board. Every lit material gets the world-space weathering patch (`render/grit.ts`, class via `userData.grit` on an ancestor); per-arena light/fog/lamps in `render/arenaLook.ts`; each arena's surroundings are their own module in `render/arenas/` (bus terminal / market / construction site) and must keep everything off the board and low on the camera (south) side. Background people are real rigs via `render/life/StreetLife.ts`; atmosphere via `render/fx/Ambient.ts`. `scripts/quick-shot.mjs` (and its `INSPECT` close-ups) is the art-review tool: judge the rendered picture.
- Mandatory endgame floor traps (0:30 and 0:15 waves) are a rule, not an option: never add a setting that disables them (decisions G3-G5).
- Characters are skinned glTF + `AnimationMixer`; animation choice derives from sim state/events in `render/views/PlayerViews.ts` only. Do not put rules in animation code.
- Audio: every sound that plays is synthesised at runtime (`src/audio/recipes`). The generated music, synthetic Pidgin voices and generated Lagos ambience from `claude/wahala-lagos-audio` were **rejected by the founder and removed**; do not generate or reintroduce music, voices or ambience. The infrastructure stays (4 persistent volumes, music player, voice director, manifests, recording slots): real licensed files are added only through `public/audio/music/manifest.json`, `public/audio/voices/recorded.json` and `public/audio/slots.json`, and `tests/audio/assets.test.ts` must then be updated deliberately. Read `docs/AUDIO.md`. Never describe synthesised sound as authentic recordings.

## Conventions
- Small modules, explicit interfaces, no god classes, no circular imports; prefer composition; inject dependencies only where it helps tests.
- Tests: scenario-style (`tests/helpers.ts` `sandbox()` etc.). Add a regression test with every bug fix.
- `base` is `/wahala-game/` for production builds (GitHub Pages). Use relative/Vite-resolved asset URLs only.
- Commit per milestone; update `docs/IMPLEMENTATION_STATUS.md`.
