# WAHALA! - project conventions for Claude Code

Browser-only, offline, single-player (1 human vs 1-3 bots) Nigerian-inspired Bomberman-style game. **Authoritative design: `docs/GAME_DESIGN_BIBLE.md`.** Architecture: `docs/ARCHITECTURE.md`. Status/backlog: `docs/IMPLEMENTATION_STATUS.md`. Tuning/rule decisions: `docs/DECISIONS.md`.

## Commands
`npm run dev` | `npm run check` (typecheck + lint + vitest + build) | `npm test` | `npm run test:e2e` (Playwright; set `WAHALA_CHROMIUM=/opt/pw-browsers/chromium` offline) | `npm run simulate -- --matches 200` (bot batches). Debug URL flags: `?debug` (window.__WAHALA__), `?fps`, `?q=low|medium|high`, `?seed=N`, `?nobots`.

## CI and releases (docs/CI.md)
- CI: plan + parallel fast checks (typecheck/lint, Vitest, one `vite build`) -> Playwright shards on separate runners (`--shard=i/N --fully-parallel`, 1 worker each, serving that build) -> merged report (`scripts/ci/report.ts` fails unless every listed test ran exactly once) -> `CI gate` -> deploy. Fix slow or hanging tests at the cause; do not raise the shard timeouts or reintroduce a single long E2E job.
- Only `.github/workflows/deploy.yml`, called by CI after the gate, publishes the Pages preview, and only from its `PUBLISH_BRANCH` with the tested `dist` artifact. Never add another publishing workflow, a manual deploy trigger or a rebuild in deploy. Old feature branches still carry publishing workflow copies: do not push to them (docs/CI.md, "Single publisher").
- Documentation-only commits (`docs/`, `reference/`, `README.md`, `CLAUDE.md`) skip the browser suite and the deploy (`scripts/ci/plan.ts`); do not push commits just to record that CI passed.

## Non-negotiable rules
- Stack: TypeScript strict, Vite, Three.js, React + Zustand (UI only), Vitest, Playwright. No backend, DB, auth or sockets.
- `src/sim` is pure and deterministic: no DOM, Three, React, `Math.random`, `Date.now`. Time = ticks (60/s). Randomness = seeded `rng.ts`. ESLint enforces this. `src/ai` may import only `src/sim`.
- No game rules in render/ui/audio/input. Rendering reads state and consumes `SimEvent`s.
- All balance numbers live in `src/sim/config.ts`. Characters/vehicles/pickups/arenas are data.
- Humans and bots send the same `Intent`. Bots only see `observe()` output, never hidden pickups or RNG.
- Game rules that are LOCKED in the Bible must not drift: generator is the primary weapon; Okada is a mount (one-hit shield, never an attack vehicle); exactly three attack vehicles (Danfo, taxi, Keke) fixed per character; vehicle damage accumulates over separate blasts; Kill-Switched generators still explode from flame/vehicles; carry adds exactly +1s once; simultaneous final deaths = draw; no health bars.
- Never reformat `docs/` or `reference/` (Prettier ignores them).
- Any gameplay/tuning change: log why in `docs/DECISIONS.md`. Never claim a feature works without a passing test or a real browser check.

## Presentation assets (overhaul branch)
- 3D models are glTF files in `src/assets/models/` generated by deterministic Python in `tools/assets/` (numpy/scipy/Pillow only; see `docs/ASSET_PIPELINE.md`). Re-run the relevant `build_*.py` after changing a generator and commit the `.glb`. Never hand-edit `.glb`/`.jpg` outputs.
- All models load through `src/render/assets/library.ts`; each consumer has a procedural fallback (`characters.ts`, `vehicles.ts`, `generator.ts`, `props.ts`) so the game still runs if a file fails to load. Conventions (Y-up, front +Z, node/material names the game looks up) are in the asset pipeline doc.
- Camera: standard matches use the fixed whole-arena camera (`render/cameraModes.ts` mode `arena`); never make it follow a player or zoom. The follow camera is the `stadium` mode, used only by City Rumble (`cityRumble`, up to 32 competitors; `?cam=stadium` forces it for testing).
- Arenas: nine standard 15 x 11 arenas + City Rumble in `src/sim/arenas/`. Arena rules and balance are `ArenaDef.config` overrides (e.g. the Power Yard full-line blast) - never `if (arenaId === ...)` in rules code. Each arena's stage hazards (`stageHazards`, `floorTraps`) are always on: no menu switch (`MatchSettings.stageHazards` is for tutorials/tests only). Presentation per new arena: `src/render/arenas/<name>.ts` (look + set + floor), registered in `newArenas.ts`. Report: `docs/NINE_ARENAS_CITY_RUMBLE.md`.
- Look: gritty, adult Lagos street life, not a bright toy board. Every lit material gets the world-space weathering patch (`render/grit.ts`, class via `userData.grit` on an ancestor); per-arena light/fog/lamps in `render/arenaLook.ts`; each arena's surroundings are their own module in `render/arenas/` (bus terminal / market / construction site) and must keep everything off the board and low on the camera (south) side. Background people are real rigs via `render/life/StreetLife.ts`; atmosphere via `render/fx/Ambient.ts`. `scripts/quick-shot.mjs` (and its `INSPECT` close-ups) is the art-review tool: judge the rendered picture.
- Mandatory endgame floor traps (0:30 and 0:15 waves) are a rule, not an option: never add a setting that disables them (decisions G3-G5).
- Characters are skinned glTF + `AnimationMixer`; animation choice derives from sim state/events in `render/views/PlayerViews.ts` only. Do not put rules in animation code.
- Audio: every effect and ambience bed is synthesised at runtime (`src/audio/recipes`). The generated music, Kokoro TTS voices and generated Lagos ambience from `claude/wahala-lagos-audio` were **rejected by the founder and removed**; do not generate or reintroduce music, voices or ambience yourself (never call a TTS service). The founder's own approved **Gemini TTS voice clips** ship: masters in `tools/audio/voices/masters/`, added only with `tools/audio/voices/import_voices.py` (which writes `public/audio/voices/voices.json` + `recorded.json` + MP3s), never by hand; the rejected `conductor_cms_01` never ships. Voice triggers are the founder manifest's names, fired from `src/audio/pidginReactions.ts`. Music only through `public/audio/music/manifest.json`, other recordings through `public/audio/slots.json`; update `tests/audio/assets.test.ts` deliberately. Read `docs/AUDIO.md`. Never describe synthesised or TTS sound as authentic recordings.
- HUD: no crowd speech bubbles or other transient text over the board. Notices, stage alerts, the arena rule and the optional subtitles (setting, default off) live in the HUD rail beside the board (`ui/HudRail.tsx`, sized from `renderer.boardScreenCorners()`); `e2e/voices.spec.ts` checks nothing covers the bottom row.

## V2 gameplay (branch `claude/wahala-gameplay-rumble-v2`, docs/GAMEPLAY_V2.md, docs/V2_CONTRACTS.md)
- Exactly two action buttons on every device: A tap = generator (`Intent.place`), A hold = Remote Detonator (`Intent.detonate`, decisions OJ2-OJ3), B tap = one deterministic context special (`Intent.special`, `sim/systems/actions.ts`: adjacent opponent -> melee, else voucher -> one-press auto vehicle, else nothing), B hold also sets off the remote (`input/specialHold.ts`: one tap/hold mechanism for both buttons). Never add a third permanent button or move them.
- Kick / punch / disarm / pass are mutually exclusive contact abilities (`Player.contact`), triggered by walking into a generator (`sim/systems/contact.ts`). Carry is out of normal play (legacy code only).
- Wahala Crush is mandatory in every standard match (no Classic Timer choice). Eliminated Classic players are sideline spectators (`systems/spectators.ts`).
- City Rumble is the flagship: Survival / Deathmatch / Team rulesets in `sim/modes.ts` (one simulation); power comes from credited eliminations (`systems/attribution.ts`, `systems/rewards.ts`), crates drop nothing in Rumble. Five V2 stages + the original district (`RUMBLE_ARENA_IDS`), one signature track each.
- Seven bot levels (`Difficulty`, `ai/profiles.ts`), Rookie default; bots press the same one-press special as humans.
- Camera shake is bounded (`render/shake.ts`), off on touch and with reduced motion.

## Conventions
- Small modules, explicit interfaces, no god classes, no circular imports; prefer composition; inject dependencies only where it helps tests.
- Tests: scenario-style (`tests/helpers.ts` `sandbox()` etc.). Add a regression test with every bug fix.
- `base` is `/wahala-game/` for production builds (GitHub Pages). Use relative/Vite-resolved asset URLs only.
- Commit per milestone; update `docs/IMPLEMENTATION_STATUS.md`.

## Stitch menu (branch `claude/wahala-stitch-uiux-v1`, docs/STITCH_UI.md, decisions UI1-UI11)
- The main menu is a short flow with no numbered steps: Home -> Mode (a tap opens the next screen) -> Arena & settings ("Select Arena" is on it) -> Fighter -> Ready/Review -> Start Match (Settings and the Training Academy beside them). Bot difficulty is one slider (`ui/menu/DifficultyControl.tsx`). Layouts: `ui/menu/flow.css` over `menu.css`. Navigation is the pure state machine `app/menu.ts` in `UiState.menu`; screens live in `src/ui/menu/` and edit the real `GameSettings` / `audioPrefs` only through `commands`. Never add a parallel setup state.
- Menu text about modes, arenas and fighters comes from the sim registries / config and `src/tutorial`; never show invented stats, ranks, locks, rewards or online features from the Stitch mockups.
- Menu art: `tools/ui/build_menu_art.py` builds `src/assets/ui/*.webp` from `tools/ui/masters/` (crops the mock HUD, removes brand marks); never hand-edit the outputs. Fonts are bundled (`@fontsource`), no CDN.
- Keyboard / gamepad menu input goes through `app/menuNav.ts` before the match; Esc in the pause menu's Settings closes Settings and keeps the match paused.
- Phones: every menu works in portrait and landscape, tap targets >= 44 px, safe areas; `e2e/menu.spec.ts` sweeps the sizes. `scripts/menu-shots.mjs` is the screenshot review tool for the menus.

## Graphics quality (branch `claude/uiux-adaptive-performance-v1`, docs/PERFORMANCE.md, decisions PF1-PF10)
- `GameSettings.quality` is `'auto'` (default) or a preset (Very Low ... High). The ladder is `src/render/quality.ts` (8 rungs, every budget non-decreasing); the device estimate, the controller and the learned rung are in `src/render/perf/`. Render-only: `src/sim`, `src/ai` and `src/input` must never see quality, and nothing in the quality system may change input timing, bomb timing, collisions, blasts or match rules.
- Add a new render budget as a field of `QualityProfile` with a value on every rung (the ladder test enforces the order), and make it LIVE (applied without a rebuild) unless it is decided at arena build; say which in the field's comment. A manual preset is never changed by Auto.
- Threshold changes go in `DEFAULT_ADAPTIVE` with a test in `tests/render/adaptive-quality.test.ts`; do not add ad-hoc FPS checks elsewhere.

## Lagos arenas (branch `claude/wahala-lagos-arenas-v1`, docs/OSHODI_METROPOLIS.md, decisions LA1-LA10)
- Source: the Canonical Lagos Map Build Bible v2; one arena at a time on the Ojuelegba pattern (graph -> sim data and tests -> real-object cover -> landmarks -> screenshots). Ojuelegba is the reference and stays unchanged. Names, signs and shops are fictional (no real brand or near-copy); no one-player bosses yet: only the reserved `ArenaDef.futureBoss` metadata, and never a real person's name, face, voice, clothing, biography or branding.
- Oshodi Transport Metropolis is `rumbleOshodiMetro`; the older `rumbleOshodi` is a separate stage. Railcars are the `train` sweep style on track lanes (`=` tiles): always warned >= 3.5 s, one step from a track-free tile, solid portal blocks at both ends, one lethal stage event at a time. The engine is single-level: "skywalk" / "grade-separated" routes are ground-level routes that share no tile with a road or track lane.
- Day and night share geometry: `ArenaArt.nightLook` is shown behind `?tod=night` (`render/timeOfDay.ts`). Cover maps are a letter per `#` (`oshodiMetroCoverMap.ts`) and must match the sim layout (tested); cover never spills over walkable floor.
- Audio for new arenas: synthesised cues only; no music, voice or recording is added without a founder assignment (default playlist until then).
