# WAHALA! 3D asset pipeline

All shipped 3D assets are **original works generated by scripts in `tools/assets/`**, exported to binary glTF (`.glb`) into `src/assets/models/`, committed, and loaded at runtime by `src/render/assets/library.ts`. The build does not need Blender. No third-party model is bundled; if one is ever added it must be listed in `docs/ASSETS.md` with its exact licence, author and source URL.

Why scripts: this environment's network policy only reaches npm, PyPI and raw GitHub files (Poly Haven, Quaternius, Kenney, Poly Pizza, Sketchfab, Mixamo, Freesound, OpenGameArt, archive.org are blocked), so downloadable CC0 packs were not available. Generating assets from code keeps provenance and licensing clean, and every asset can be regenerated and tuned.

## How the assets are made

Everything is built by deterministic Python scripts in `tools/assets/` that need only **numpy, scipy and Pillow** (`pip install numpy scipy pillow`). A tiny dependency-free glTF writer (`gltfio.py`) emits the `.glb` files, including skins, animation clips and embedded JPEG textures. Blender (`bpy`) was evaluated as the primary tool but its 400 MB wheel is impractical in the sandbox network, so the pipeline does not depend on it.

| Script | Produces |
| --- | --- |
| `loft.py`, `chargen.py`, `outfits.py`, `characters.py`, `rig.py`, `build_characters.py` | the three rigged, animated playable characters (`char_*.glb`, 16 clips each) |
| `crowd_lib.py`, `build_crowd.py` | `crowd.glb`, twelve posed, clothed spectators (CPU-skinned from the same bodies) |
| `prim.py`, `tex.py` | hard-surface modelling kit (bevelled boxes, lathes, tori, prisms, decals) and procedural PBR texture synthesis (concrete, asphalt, wood, painted metal, corrugated iron, plaster, brick, rubber, posters) |
| `build_vehicles.py` + `vehicles_lib.py` | `veh_*.glb`, `gen_generator.glb` |
| `build_environment.py` + `env_lib.py` | `prop_*.glb`, `env_*.glb` (pillars, soft blocks, walls, buildings, kiosk, lamps...) |
| `build_textures.py` | `src/assets/textures/floor_*.jpg` (the 4x4 concrete-slab atlas); `build_textures.py market` -> `market_*.jpg` (interlock pavers, `tex_market.py`) |
| `env_market.py`, `tex_market.py` (`build_environment.py market`) | Balogun Market: `mkt_hard_post`, `mkt_hard_counter` (tiles seamlessly along X), `mkt_soft_{fabric,produce,buckets,baskets}`, `mkt_wall`, `mkt_wall_b`, `mkt_wall_corner`, `mkt_stall`, `mkt_umbrella`, `mkt_fabric_rack`, `mkt_building_a/b` |
| `env_busterminal.py` (`build_environment.py busterminal`) | Danfo Bus Park terminal dressing: `bp_shelter`, `bp_barrier`, `bp_sign`, `bp_booth` |
| `veh_parked.py` (`build_vehicles.py parked`) | `env_danfo_parked.glb`, the 1.6k-triangle background danfo (LOD for the parked ranks) |

```bash
pip install numpy scipy pillow
python3 tools/assets/build_characters.py    # char_*.glb
python3 tools/assets/build_crowd.py         # crowd.glb
python3 tools/assets/build_vehicles.py      # veh_*.glb, gen_generator.glb
python3 tools/assets/build_environment.py   # prop_*.glb, env_*.glb
python3 tools/assets/build_textures.py      # floor textures
```

Assets are deterministic (seeded) and committed; the Vite build only needs the committed `.glb`/`.jpg` files.

## Conventions every model must follow

- **Y-up, metres, front = +Z** (glTF convention). Origin on the ground at the model's footprint centre (vehicles: between the wheels' contact patches).
- **Names** (the game finds parts by name):
  - Vehicles: wheels are separate nodes named `wheel_FL`, `wheel_FR`, `wheel_RL`, `wheel_RR` (Keke: `wheel_F`, `wheel_RL`, `wheel_RR`; Okada: `wheel_F`, `wheel_R`) with their **origin at the axle centre** and the axle along local **X** (the game spins them about X). Optional: `steering` node for the front fork/handlebars.
  - Generator: a node `lamp` (emissive indicator light), node `antenna` (remote aerial), `casing` material for the body paint.
  - Characters: a skinned mesh with one armature; the exact clip list is in `tools/assets/characters.py` (Idle, Run, RunCarry, IdleCarry, Ride, Place, Kick, Throw, Stumble, Cheer, Win, Lose, DieBlast, DieVehicle). Bodies are passed through `chargen.stylise()` and heads (region `head`) are enlarged by `build_characters.HEAD_SCALE` about the chin; the crowd uses the same bodies and head scale.
  - Crowd: one node per pose, named `spec_<name>_<role>_<frame>` with role `watch` | `talk` | `walk` and frame `0` (calm / first stride) or `1` (reaction / second stride). The game pairs the frames by name.
- **Budgets** (mobile friendly): characters <= 9k triangles, <= 5 materials; vehicles <= 8k triangles, <= 8 materials (the Session E danfo/taxi/Keke are 9.4k/8.5k/8.9k, accepted because at most three drive at once; background copies use the low-poly `env_danfo_parked`); props <= 2k triangles, 1-2 materials; buildings/kiosks <= 3k triangles each. Textures power-of-two, <= 1024 px (vehicles, characters), <= 512 px (props); prefer one shared atlas per model. Whole `src/assets/models` target: <= 15 MB.
- **Static props that the game instances** (pillars, crates, tyre stacks, barriers, sacks) must be **a single mesh with a single material** so they can be rendered with `InstancedMesh`.
- Materials are glTF PBR (metallic-roughness). Emissive only where something really glows (lamps).
- Smooth shading with sensible normals and bevelled edges; no hard black seams; UVs unwrapped; no flipped normals.
- Export through `prim.Model.export(...)` (static assets) or `build_characters.py` (skinned).

## Previewing

`tools/viewer/viewer.html` is a dev-only page that renders a GLB under the game's lighting/camera:

```bash
npm run dev -- --port 5199 --strictPort &            # Vite dev server
export WAHALA_CHROMIUM=/opt/pw-browsers/chromium
node tools/viewer/shot.mjs out.png "model=/src/assets/models/danfo.glb&view=three&scale=1" 900 700
# params: view=game|front|back|side|three|top|close|head, clip=Run, t=0.3, rot=30, models=a.glb,b.glb (side by side), grid=0, bg=hex
```

It prints triangle/mesh/material/bone counts and the clip list. **Always inspect the screenshot** from at least the in-game view (`view=game`) and one close view before calling a model done.

For whole-scene art reviews against `reference/`, `tools/viewer/gameshot.mjs` screenshots the real game (4 players, seed 7) at chosen simulation ticks:

```bash
node tools/viewer/gameshot.mjs out/shot 1280 720 high 300 330   # -> out/shot-300.png, out/shot-330.png
node tools/viewer/gameshot.mjs out/phone 844 390 medium 300     # landscape phone (touch, 2x DPR)
MOUNT=1 DSF=2 node tools/viewer/gameshot.mjs out/okada 1280 720 high 230   # everyone on an Okada, 2x
```

Arena art lives in themes (`src/render/themes/`): each arena id names its floor texture set, permanent/destructible models (with weights), wall set and surroundings, so a new arena's assets only need new ids there. Destructible props must stay single-mesh/single-material; a theme's joined permanent model must span exactly x in [-0.5, 0.5].

For vehicles in the real game, `tools/viewer/vehicleshot.mjs <outPrefix> [arenaId]` launches each signature vehicle from the gameplay camera and writes a full frame plus a crop around the vehicle; `ARENA=balogunMarket node tools/viewer/gameshot.mjs ...` captures the market.

## Regeneration

Run the scripts, rebuild, and rerun the e2e suite. Asset provenance and licensing live in `docs/ASSETS.md`.
