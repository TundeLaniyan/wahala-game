State on `claude/wahala-nine-arenas-city-rumble` (started from `claude/wahala-gritty-gameplay-v1`): **one signature
track per standard arena** (see "Signature tracks" below) and the music bus raised by +2.5 dB. The approved-playlist music system (`src/audio/playlist.ts`,
`src/audio/music.ts`, `src/audio/escalation.ts`) with **fourteen of the fifteen approved tracks installed and playing** (V2 added five City Rumble stage tracks on 2026-10-25, one signature track per V2 Rumble stage).

**Voice integration (`claude/wahala-voice-integration`, 2026-10-24):** the founder's Gemini text-to-speech Pidgin
voice clips now play (30 of the 47 planned lines: 19 in the first batch, 11 more added in V2 on 2026-10-25), on their own voice bus, mapped to game events,
loaded per arena; see "Voice lines" below. The crowd's on-screen speech bubbles are gone (optional subtitles instead).

## Layers and volumes

```
music   music.ts: streamed playlist track       -> musicDuck -> musicBus ----\
sfx     effects                                   -> sfxBus -------------------+
warn    danger warnings (never ducked)            -> warnBus (sqrt sfx vol) ---+-> master -> limiter -> out
react   crowd reactions                           -> notch -> reactDuck -> crowdBus
amb     ambience beds + background conversations  -> notch -> ambDuck  -> crowdBus
voice   foreground voice lines (never ducked)     -> voiceBus (1.3 x sqrt ambience vol) ------------/
```

`src/audio/prefs.ts` holds four independent persistent volumes (localStorage key `wahala.audio.v2`; corrupt or
unavailable storage falls back to the defaults) plus the voices on/off switch. The defaults are the music-first
**recommended mix** (founder, 2026-10-24, decision M8):

| Slider | Default | Controls |
| --- | --- | --- |
| Master | 85% | everything |
| Music | 90% | the arena's signature track |
| Ambience & voices | 45% | crowd beds, crowd reactions, spoken lines |
| Effects | 50% | synthesised effects; danger warnings follow it on a square-root curve |

`src/ui/AudioSettings.tsx` shows them on the title screen and the pause menu, with mute (stored in the existing
`GameSettings.muted`, shared with the HUD button), the voices switch and the **Recommended mix** button (reads
"Recommended mix ✓" while the mix is the recommended one, "Use recommended mix" otherwise; one press restores it and
saves it). The engine follows the store itself; the legacy `setVolumes()` is ignored while a store is active.

Existing players: nothing is stored until someone moves a slider, so a player who never touched the mix gets the
new one automatically. A mix saved by an older version (key `wahala.audio.v1`) is migrated once on load: if it still
equals the old defaults (80 / 45 / 65 / 85) it becomes the recommended mix; a mix the player chose is kept, with its
music slider converted for the new music bus (x 1.73, rounded to the 5% step) so it sounds as loud as before. The
old key is left untouched and never read again once `wahala.audio.v2` exists.

Gain staging (measured with ffmpeg on the nine shipped tracks): each track's manifest `gain` levels it to about
-14 LUFS; the music bus is unity (`MUSIC_BASE = 1`), so the 90% slider and 85% master put the music at about
-16.8 LUFS after the master limiter, which takes about 0.9 dB off its peaks on average (1.6 dB at most); no peak
reaches the soft clipper's full scale. The louder default comes from the slider alone: the +2.5 dB music-bus lift of
decision N13 was removed so the boost is not applied twice (with it the limiter would have taken 1.6-2.5 dB off the
music and pumped on every kick). Compared with the old defaults the music is about 1.5 dB louder and the effects
4.6 dB quieter, so the music sits about 6 dB further forward. Danger warnings use `0.8 * sqrt(effects)` (1.6 dB
below the old level at the 50% default), and the music dips deeper for them (to 0.5) and for big blasts (to 0.45),
so trap alarms, horns, fuse ticks and explosions still cut through. Nobody has listened to it yet (no audio output
in the build container).

Lifecycle: nothing is created before the first user gesture (`unlock()`); `startMusic(arenaId)` enters the match
soundscape (and picks this match's track), `setPaused(bool)` follows the pause menu, `stopMusic()` leaves the match
(ambience fades, generator/engine loops stop, menu music if any), `dispose()` stops everything, unsubscribes from the
preferences and closes the context. All loaders resolve (never reject) and stay silent when files are missing or
fail to decode.

### Availability at runtime

After the first gesture the player fetches the manifest and probes each listed file once (a `HEAD` request; a
dev-server HTML fallback page does not count as a track). A file that is missing, or that later fails to play, is
skipped silently (the game logs nothing; the browser itself may still log the 404 of a probe). With zero files the
music is silent and everything else works. `whenMusicLoaded()` reports which ids were found.

### Rotation and arena playlists (`src/audio/playlist.ts`)

- Each match (`startMusic(arenaId)`, called by `MatchController.start` with `settings.arenaId`) picks a track from
  that arena's playlist, uniformly among the available ones, **never the previous match's track** while another one is
  available. Rematches therefore always change track once two or more files are present. The randomness is injected
  (`AudioOptions.musicRand`, seeded from the clock by default) so tests are deterministic.
- `playlists.default` lists all ten; `playlists.arenas.<arenaId>` gives an arena its own `tracks`, a `start` track and
  an optional `signature`. A signature (meant for when there are ten arenas, one track each) always plays on its arena
  while available. The `start` track opens the **first** match on that arena in a session (unless it was the track
  just heard); later matches rotate through the arena's list, never repeating the previous track.

### Licensing in a public repository and a public GitHub Pages build

The repository is public and GitHub Pages serves static files, so every MP3 is technically downloadable by anyone who
looks at the network requests or the repository. Nothing here pretends otherwise. What keeps the use within the
Pixabay Content License is how the files are offered: as the soundtrack inside the game, loaded by the game's player,
named by slot, with no download button, album page, ZIP, playlist page or "soundtrack" section, and the source pages
credited in `public/audio/LICENSES.md`. The licence forbids distributing the music on a standalone basis; a public
repository holding the files of a game that uses them is the normal way games ship licensed music, but it is the
founder's call whether to keep the MP3s in the public repository or move them to private storage / a CDN before a
commercial release (that would need a small change to where `music.ts` fetches from). Re-read the licence before
any commercial launch.

### Streaming

Tracks stream through an `HTMLAudioElement` (one per playing track, released when it has faded out) routed into the
Web Audio graph with a `MediaElementAudioSourceNode`, so ten tracks never sit decoded in memory:

```
<audio> -> deck gain (crossfades) -> high shelf -> punch peak -> trim -> pause gain -> musicDuck -> musicBus
```

The music therefore still obeys the user's music volume and is still ducked under blasts, warnings and speech.
Crossfades: 1.0 s in, 1.2 s match to match, 1.6 s back to the menu. A track loops if a match outlasts it.

### Endgame escalation (`src/audio/escalation.ts`)

Synchronised to the game clock (`(durationTicks - playTicks) / 60`, read in `handleEvents` every tick; match timing is
not touched). From 30 s remaining an urgency value eases from 0 to 1 (smoothstep, so there is no step at 30 s):

| Remaining | 45 s | 30 s | 15 s | 0 s |
| --- | --- | --- | --- | --- |
| Playback rate (pitch preserved) | 1.000 | 1.000 | 1.045 | 1.090 |
| High shelf at 3.2 kHz | 0 dB | 0 dB | +1.75 dB | +3.5 dB |
| Punch peak at 110 Hz | 0 dB | 0 dB | +1 dB | +2 dB |
| Compensating trim | 0 dB | 0 dB | -0.9 dB | -1.8 dB |

- Tempo uses `preservesPitch = true` (or the `webkit` / `moz` prefixed property). Where pitch cannot be preserved the
  rate is **never** changed; only the brightness/drive lift applies. Rates are written in 0.0025 steps (36 writes
  over the last 30 s), not every frame.
- The escalation starts with the mandatory floor traps: wave 1 goes live at 0:30 (urgency starts rising), wave 2 at
  0:15 (rate about 1.045), and Wahala Crush's last tiles close towards 0:00 (rate 1.09). The trap alarm and the floor
  giving way also duck the music briefly (`buses.duck('warning' | 'blast')`), so each wave lands as a beat.
- The trim is an estimate meant to keep the escalated music at or below its normal level; it has not been checked by
  ear. Effects and warnings are on other buses and untouched; ducks still apply.
- Match end: the tempo eases back to 1.0 (0.06 per second), the tone resets and the track settles to 55% until the
  results screen (`stopMusic`) fades it out.
- Pause (`MatchController.setPaused` -> `audio.setPaused`): a 120 ms fade, then the stream pauses; resume continues
  the same track from the same point. Hiding the tab pauses the match, so the music pauses too.
- Mute: the master fades to 0 as before; the music keeps following the clock, so unmuting lands on the right tempo.
- Rematch: a new track, tempo 1.0, tone reset, un-paused. Quit to title (also from the pause menu): the match track
  fades out and its stream is released.

At runtime (`src/audio/pidgin.ts`) a line plays only if it is in the catalogue, not rejected, listed in
`recorded.json` with a licence statement and a safe file name, and its trigger is one the game fires
(`VOICE_TRIGGERS`). Everything else is ignored and reported (`whenVoicesLoaded()`), never thrown.

### Loading (mobile)

- Nothing before the first gesture (the existing unlock); after it, only the two small JSON manifests.
- The title screen loads no clip. When a match starts (`startMusic(arenaId)`), the clips that can play on that
  arena are fetched in the background, two at a time, most urgent first (priority 1 lines, then 2, background
  conversations last); a Danfo Bus Park match fetches the 18 everywhere-lines (about 0.3 MB), a Balogun Market match
  adds the market line. The match never waits for them; a line simply cannot play until its clip has decoded.
- Decoded clips stay cached for the session; a clip that fails (404, not audio) is recorded once and never
  requested again; the others play normally.

### Director rules (unit-tested)

- One foreground line at a time. A **forced** line with a more urgent priority (lower number) cuts the current
  one short (60 ms fade): e.g. "Oga! Run o!" interrupts "See Keke!". Otherwise a new line waits its turn (is dropped).
- After a line, its trigger rests for that line's manifest `cooldown` (3-15 s); unforced lines also keep 4 s
  between starts; identical triggers within 0.6 s collapse; shuffle bag per trigger, a line is not repeated within
  40 s, the previous speaker is avoided; a refused request does not use up a line.
- Background conversations: one at a time, a 7-15 s gap (shorter when the match is lively), never while a
  foreground line speaks (held 2.5 s after one), each line rests at least 40 s; ducked to 20 % under a foreground
  line and cut by an urgent one. Forced = the human's danger warning, own elimination, Okada save, victory, final 30 s.

### Mixing

- Foreground lines go to the new **voice bus** (`buses.ts`): no warning-band notch (it would remove the consonants),
  never ducked, a +3 dB presence lift at 2.5 kHz, and it follows the "Ambience & voices" slider on a square-root
  curve (`1.3 x sqrt(ambience)`, 0.87 at the 45 % default) so speech stays intelligible in the music-first mix.
- While a line speaks the music ducks to 0.5 (ordinary line) or **0.4 (urgent line)** and the crowd beds to
  0.4 / 0.3, then recover smoothly (0.35 s time constant) when the line ends; the voice itself is never ducked.
  Estimated at the defaults: a -16 LUFS clip plays about 3.5 dB above the ducked music (5.5 dB for an urgent one).
- Background conversations stay on the notched, ducked ambience path at 0.9 x 0.36 and through a 3.8 kHz low-pass:
  about 8 dB quieter than a foreground line, and they never duck the music.
- Headroom: the loudest clip peaks at -1.3 dBFS; at the default mix a voice peak reaches the master limiter at
  about -4 dBFS or lower (`tests/audio/assets.test.ts` checks every clip stays below -3 dBFS there); the existing
  limiter and soft clipper guarantee no output overs whatever the sliders (`buses.ts`).
- User volumes, mute, the voices on/off switch, the nine arena tracks and the endgame tempo escalation are unchanged.

### Subtitles (setting: Off by default / On / Large)

Title screen and pause menu, saved with the game settings. When on, the text of the line playing now appears in
the HUD rail beside the board (urgent lines with a red edge, background talk in italics), for the line's length
(at least 1.6 s), one at a time. A trigger with no clip shows nothing.

### Adding voice clips (the next batches)

1. Put the new WAVs (file name = the manifest `filename`, e.g. `okada_saved_01.wav`) in any folder. Rejected
   takes stay out (anything in a `rejected/` subfolder is never looked at).
2. Run `python3 tools/audio/voices/import_voices.py --add /path/to/folder` (needs numpy and ffmpeg). If the plan
   changed, add `--manifest /path/to/manifest.json`. It copies the masters, validates them, re-encodes everything
   and rewrites `voices.json` and `recorded.json`; lines whose status is REJECTED are never imported.
3. Update the expected list in `tests/audio/assets.test.ts` ("the first batch") deliberately, run `npm run check`,
   listen in `npm run dev` (`?debug` and `__WAHALA__.previewVoice('ON_OKADA_SHIELD_SAVE')` plays one), commit.
No game code changes: every planned trigger is already wired, and a new clip of an existing trigger joins its
rotation. A genuinely new trigger name needs one entry in `VOICE_TRIGGERS` and its detection in
`pidginReactions.ts`. To retire a clip, delete its master and re-run the importer.
