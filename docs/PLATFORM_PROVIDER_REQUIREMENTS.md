# What each external provider needs before anything here goes live

Nothing below exists today: no account has been created, no credential is held, no live call was ever made. "Verified in tests" means the platform's own verification code, driven with locally generated keys.

| Provider | What the founder must create / decide | What engineering then builds | Status in code |
| --- | --- | --- | --- |
| **Google sign-in** (web, Android) | a Google Cloud project, an OAuth consent screen (app name, privacy policy URL, verification for sensitive scopes: only `openid email profile` are needed), OAuth client ids per platform (Web, Android with the signing-key SHA-1, iOS) | set `PLATFORM_GOOGLE_CLIENT_IDS` (all client ids that may be the token `aud`); client obtains an id token with a server nonce from `/v1/auth/nonce` | **verifier built and tested with local keys** (issuer, audience, expiry, nonce, algorithm); never run against live Google |
| **Sign in with Apple** (required by Apple if any third-party login is offered on iOS) | Apple Developer Program membership (annual fee, set by Apple), App ID with the capability, a Services ID for web, return URLs, private-relay e-mail domain registration if mail is ever sent | set `PLATFORM_APPLE_CLIENT_IDS` (bundle id / Services ID); client passes the nonce | verifier built, same status. Apple may return a private-relay address: the platform stores only a masked hint |
| **Apple In-App Purchase** | Apple Developer account, App Store Connect app record, agreements / tax / banking forms, product ids per item (consumable vs non-consumable decided per item), sandbox testers | `AppleIapProvider`: verify the StoreKit 2 signed transaction (JWS, certificate chain to Apple's root) or call the App Store Server API; consume App Store Server Notifications V2 (refund, revoke); restore-purchases flow; map `productId` via `store_products`; fill `amountMinor: null` (Apple sets the price) | skeleton, 501 |
| **Google Play Billing** | Google Play Console developer account (one-time fee), app record, merchant profile, in-app products, licence testers | `GooglePlayProvider`: verify the purchase token with the Play Developer API (service account), **acknowledge within 3 days**, consume Real-time Developer Notifications (Pub/Sub topic) for refunds / voids | skeleton, 501 |
| **Web checkout** (Nigerian cards, bank transfer, USSD, mobile money: processor to be chosen) | a business bank account and processor account (KYC), settlement currency, fee schedule, chargeback policy, a business entity able to contract | `WebCheckoutProvider`: hosted-checkout session with our order id as reference and the **server-side** price; webhook verification over the raw body; map their event names; reconcile daily | skeleton, 501 |
| **Voice media server** | a hosting account for the SFU and TURN (or a managed voice vendor contract) | `VoiceGateway` implementation (`PLATFORM_VOICE_DESIGN.md`) | seam only, 503 |
| **Moderation vendor** (optional) | a vendor evaluated on Pidgin / Yoruba / Igbo / Hausa samples | `TextModerator` implementation behind the existing interface (fails closed) | interface only |
| **E-mail / push** (not built) | a sender domain, FCM / APNs credentials | notifications for requests and invitations (today clients poll) | not built |

Store rules that also bind the game (verify the current text before submission): Apple and Google both require in-app purchase for digital goods sold inside the app on their platforms (web checkout cannot be linked from the iOS / Android app where the store's rules forbid it); both require age-appropriate handling of purchases and user-generated content; both require an account-deletion path inside the app for apps that create accounts (`POST /v1/me/delete` exists; the client must expose it).
