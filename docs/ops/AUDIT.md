# Audit of the standalone server bundle (2026-11-24)

Subject: `server/` @ `f7cf2ae`, bundled with `npm run bundle` (one 4.1 MB ESM file, only `@colyseus/core` and `@colyseus/ws-transport` as dependencies, runs with plain `node` outside the repo). Method: read `server/src`, ran the server suite (typecheck clean, **18 files / 193 tests passed**, 117 s), then probed the running bundle as a black box (`ops/scripts/`). No server file was modified.

## What the bundle needs to run

Node 22, one TCP port (default 2567, plain `ws`/HTTP, `0.0.0.0`), environment only: `PORT`, `RUMBLE_ALLOWED_ORIGINS`, `RUMBLE_METRICS_TOKEN`, `RUMBLE_GRACE_SECONDS`, `RUMBLE_RECONNECT_SECONDS`, `RUMBLE_DROP_POLICY`, `RUMBLE_PING_*`. No database, disk, cache, outbound network or accounts. State is in memory: a restart ends every match (acceptable now, see RELEASE_GATES). SIGTERM/SIGINT shut down gracefully (clients get close code 4001; exit 0 in 164-242 ms in a container). TLS, rate limits and logging policy are not in the server.

## Findings

Severity: **High** = blocks public hosting; **Medium** = fix before wider testing; **Low** = note. Owner: *Ops* = handled in `ops/`; *Arch* = needs a change in files Architecture owns (not made here).

| # | Finding | Evidence | Sev | Status / owner |
| --- | --- | --- | --- | --- |
| F1 | `/metrics` is served to anyone when `RUMBLE_METRICS_TOKEN` is unset, **even with `NODE_ENV=production`**; it shares the public port. The token check is a plain `!==` (not constant time). | `curl localhost:2599/metrics` returned process and room data with no credentials | High until mitigated | **Mitigated (Ops):** edge returns 404 for `/metrics`; token required in the env template; monitor reads it on the private network. *Arch (small):* refuse to start in production without a token. |
| F2 | No limit on room creation. One address created **2 000 rooms in 1.9 s** (about 1 050-1 360 per second). Idle rooms disposed 15-20 s later (seat reservation); +60 MB heap and event-loop p99 49 ms during the flood. | `abuse-probe.mjs create-flood` | Medium | **Mitigated (Ops):** nginx `/matchmake/create/` 6 per minute, burst 4 per address; measured 4-5 of 300-500 allowed. |
| F3 | **A started room is the real DoS.** Any guest who creates a private room is its host and can start it: 32 fighters, 31 server bots. Measured on this 4-vCPU box: **1 room ≈ 37 % of a core (p50, max 45), 3 rooms ≈ 74-87 % (max 116 %)**, timer-lateness p99 up to 54 ms, 0-3 dropped ticks; earlier docs measured 4 rooms ≈ 94 % with 47 dropped ticks. There is no global cap on playing rooms and no per-address cap, so a few rooms make every player's match run in slow motion. | `abuse-probe.mjs start-flood` | **High** | **Not fixable at the edge** (starting is a message inside an open socket). Interim (Ops): IP allowlist, supervised sessions only, one process per vCPU, container CPU/memory limits, `capacity`/`dropped-ticks` alerts. **Needed (Arch):** a per-process cap on concurrently *playing* rooms (answer `server_busy`), a per-address cap on live rooms, and ideally a cheaper filler-bot level. |
| F4 | The origin allowlist only constrains browsers. Scripts send no `Origin` and are accepted on both the upgrade and `/matchmake/*`; a hostile origin still got HTTP 200 on a create. | `smoke.mjs` INFO line; `curl -H 'Origin: https://evil.example' -X POST /matchmake/create/rumble` → 200 | Medium | Documented. It stops casual cross-site page abuse, not scripted abuse. The edge limits are the control. |
| F5 | The server never learns the client address behind a proxy and has no per-address logic. Mobile carriers and Wi-Fi put many phones behind one address (CGNAT), so per-address limits must be generous. | Source review; edge limits chosen with this in mind | Medium | Design note. Limits in `nginx.conf` are starting values; tune from the first supervised test. |
| F6 | `/health` is liveness only: `{"ok":true}` whenever HTTP answers, even if the tick loop is dropping ticks. | Source; the overload runs still returned ok | Medium | Monitoring reads `/metrics` (event loop, dropped ticks, step/lateness) as the real readiness signal: `MONITORING.md`. |
| F7 | `server/Dockerfile` was never built (its header says so), needs a host-built `dist/`, has no health check, no `.dockerignore`, floating base image. | Read; replaced by `ops/docker/Dockerfile`, which was built and validated | Medium | **Done (Ops)** without editing Architecture's file. *Arch:* adopted; the old file was deleted (FU2-D1). |
| F8 | `RUMBLE_TEST_FAST=1` lets clients choose countdown, start time and match length. Harmless in tests, dangerous if ever set in a reachable deployment. | `options.ts` | Medium | Env template forbids it; `check` in RELEASE_GATES. *Arch:* ignore it when `NODE_ENV=production`. |
| F9 | Guest names: well defended (NFKC, bidi/zero-width, mixed-script, `BOT` look-alikes, duplicates renamed) and tested. No profanity or reserved-word filter ("Admin", "WAHALA Team"), no report/mute. Names are the only player-written text; there is no chat. | `server/test/identity.test.ts`; `smoke.mjs` 5/5 abusive names refused | Low-Medium | Add a small deny-list before public play (*Arch*). |
| F10 | Reconnection tokens: Colyseus random 9-character secrets (~54 bits), single use, rotated on every connection, never shown to other members; not bound to an address (correct: phones change address mid-match). Forged and borrowed tokens refused. | `smoke.mjs` 5/5 refused; `identity.test.ts` | Low | Good as is. The matchmake zone also throttles guess attempts. |
| F11 | Server logs contain **private room codes** (`room 5RAVZ5 created (private)`), which are the only protection of a private room. | `run.log` of the bundle | Low-Medium | Ops: logs rotated (3 × 10 MB), never shipped by default, treat as sensitive; nginx logs only the route class. |
| F12 | Positive: WebSocket frames are capped at 4 KB by the transport (a 4 KB payload frame was closed with code 1009); invalid-message and flood kicking exist and are tested; the server holds no secrets and no personal data. | Probe + `RumbleRoom.ts` | - | Keep. |

## What this audit did not cover

No code review of the simulation, no fuzzing of the binary protocol beyond the 4 KB frame check, no dependency CVE scan (run `npm audit` and an image scanner in CI before launch), no penetration test, no volumetric DoS test (that is the provider's layer).
